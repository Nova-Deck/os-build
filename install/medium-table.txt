# novadeck INSTALLER MEDIUM partition table. Phase 6 of .claude/plans/internal-install.plan.md.
#
# TWO partitions, and that is the whole difference from the shipped card: there are no slots here.
# The installer boots once, writes NovaDeck to the device's internal disk, and is thrown away — so
# there is nothing to update atomically, nothing to roll back to, and no /home to preserve. A/B on
# a recovery medium would be machinery guarding a property nobody wants.
#
#   p1 esp    the boot partition AND the log destination. It is an EFI System partition (ef00)
#             because ABL finds it by type GUID and loads \EFI\BOOT\bootaa64.efi from it, and it is
#             the ONLY ef00 on this disk so there is no candidate for it to choose between. It is
#             also mounted at /esp by the root's fstab: install/save-log.sh copies the install log
#             here, and a FAT partition on removable media is the one artifact that can leave a
#             device that failed to install — pull the card, read it on any PC.
#   p2 root   the read-only squashfs. Sized by install/mkimage.sh from the actual filesystem, not
#             declared here: the size is an output of what got built, and a fixed number would
#             either waste medium or fail the fits() check on a package addition.
#
# THE FAT LABEL IS NOT A `novadeck-*` ONE, deliberately. A dev card and an internal install already
# share those labels, which is exactly why REPLACES_OURS=1 cannot be judged from a dev card — and an
# installer whose /esp matched the TARGET's ESP would mount the disk it is about to overwrite and
# write its failure log there. NDINSTALLER is 11 characters, all a FAT label has room for.
#
# ON FAT WIDTH, because images/partition-table.txt carries a loud warning against forcing -F 32 and
# this file does force it (install/mkimage.sh, like images/make-sdcard.sh). The warning is about
# 4Kn media: a 256M FAT32 has 65376 clusters at 4096-byte sectors, below the 65525 a FAT32 must
# have, and ABL's FatPkg then refuses the volume outright. It does not apply here for two
# independent reasons — the filesystem is built INSIDE AN IMAGE FILE, where mkfs.vfat sees 512-byte
# sectors whatever the eventual target is, and the installer medium is removable (SD or USB), all
# of which is 512e. Every internal UFS in this fleet is 4Kn; none of it is ever this partition.
# If an installer image is ever targeted at 4Kn media, this is the line that breaks first.
#
# esp is 256M for headroom, not need: GRUB is ~2.3M, the kernel Image ~40M and the dtbs ~2M. The
# slack is for the log, and for a future initramfs if the read-only-/etc decision is ever revisited.
#
# The ESP carries NO GPT bit 63 here, unlike the shipped card. That bit exists to stop systemd's
# gpt-auto generator claiming /efi, a name the shipped initramfs reserves for the slot's efi
# partition. This medium has no initramfs, no slots and no /efi — and the fstab entry naming
# LABEL=NDINSTALLER is the only mount definition either way.
#
# Consumed by images/genpart.sh exactly as the shipped table is. Row order = partition number.
#
# IT IS CALLED medium-table.txt, NOT partition-table.txt, and the name matters. install/mkroot.sh
# ships images/partition-table.txt — the EIGHT-partition A/B layout — into the installer's flat
# directory under that exact basename, because the spine carves the TARGET disk with it. Two files
# named partition-table.txt, one describing the medium and one describing what the medium installs,
# is a mistake waiting to be made by whoever next edits either.
#
# name      size  typecode  fs         label            attrs
esp         256M  ef00      vfat       NDINSTALLER      -
root        rest  8300      squashfs   novadeck-instrt  -
